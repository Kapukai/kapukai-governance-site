# Kapukai navigation and discovery

## Decision

Preserve the approved Workshop identity and five existing global categories: Tools, Explore, Learn, Participate, About. Replace three stacked rows with grouped disclosure navigation, a compact breadcrumb, member sign-in utility and a single participation action. Member forms and authentication stay unchanged. No hover-only interaction is required.

## Reference models

These are independently observed examples, not a ranking or a universal billionaire standard:

- Gates Foundation separates institutional information, how it works, funding and policies: https://www.gatesfoundation.org/about
- Apple maintains a grouped human-readable directory alongside global navigation: https://www.apple.com/sitemap/
- W3C recommends semantic labelled navigation, meaningful structure and current-location cues: https://www.w3.org/WAI/tutorials/menus/structure/
- Google recommends canonical absolute sitemap URLs and excludes URLs not intended for search: https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap

## Single navigation registry

`community/navigation.py` defines groups used by the shared header, grouped footer and human directory. `community/discovery.py` discovers generated public canonical HTML routes for the XML sitemap and additional directory entries. All links are real destinations; no placeholder search or invented member directory is added.

The human directory can link to the member access page. The XML sitemap excludes members, operations and private confirmation/application routes. noindex is a discovery directive, not access control; existing backend authorization remains responsible for member privacy.

## Publication boundaries

Community shared pages deploy to the existing `kapukai-community` Vercel project. The root kapukai.org homepage, Bills module and other applications are separate owners. The header links to their canonical public pages without moving DNS or replacing their content.

The authored Join page and separate newsletter archive retain their existing layouts. Navigation updates cover pages generated by the community shared template; this is not a claim that every independently hosted Kapukai application already uses the same shell.

After Vercel verification, `ops/navigation/install.py` installs only the navigation release's changed static files on the existing canonical host. It validates expected old and new hashes, downloads and verifies all inputs before writes, backs up files, and verifies public served hashes. A baseline mismatch stops the whole installation. No credentials, nginx edits or mail configuration are included.

## Maintenance

Add destinations to the shared registry rather than hand-editing every menu. Run the generator and navigation/discovery tests. Preserve old URLs or provide explicit redirects when routes move. Record commit, Vercel deployment and canonical verification in the release record. The public release remains pending until canonical URLs serve the matching files.
