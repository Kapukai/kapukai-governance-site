# Document pilot preparation release — October 20, 2026

## Implemented

- Blank scope-and-use template for an affidavit draft, timeline or dossier; bounded engineering at $250/hour.
- Six-step operator guide and copyable metadata checklist using native HubSpot deal fields. Sales stage remains separate from fulfillment.
- Pure metadata review helper and command-line entry point. The helper reports a phase, one next action, blockers and actual closure category.
- Scope document digest and version binding; provider-readback references and amount/currency/environment checks; capacity and permitted-processing checks; reviewed output versions; delivery/acceptance separation; correction and cancellation/refund paths.
- Entirely fictional reusable sample. No private customer records added to GitHub.
- One internal setup task created in HubSpot, associated with the existing Kapukai Governance Lab company and assigned to the existing owner. Independent readback confirmed the task content, owner, status and review date. The October 22 review date is an internal target, not a customer promise.

## Verification

19 focused Node tests pass for normal progression and concrete failure paths. Tests use fictional assertions; they are not an authenticated end-to-end transaction. Repeated evaluation is deterministic and has no side effects, but the helper does not implement provider idempotency or prevent direct edits in HubSpot.

The CLI demo and invalid-input behavior were checked. No browser UI was changed or deployed in this release.

## Connection results

- HubSpot custom-property creation returned `UNAVAILABLE / Unknown tool: invalid_tool_name`. Readback found none of the three proposed custom fields. The workflow therefore uses existing Deal Description, Next step, owner and associated task fields; no new pipeline is required.
- The first unassociated task create was rejected without creating a record. Associating the setup task with the existing Kapukai company succeeded; no fictional commercial deal or real-client association was created.
- Only the existing Stripe sandbox was available. A synthetic-customer create request was interrupted before a result. A subsequent metadata search returned zero matches. It was not blindly repeated. No invoice, charge or refund was created or verified in this release.
- No customer messages were sent. Supabase, Postmark, public signups, current free offers, public hosting and domain settings were unchanged.

## Before a real paid order

1. Complete and release a concrete scope, use permissions, correction/cancellation/refund terms and actual payment schedule. The blank template is not an effective agreement or customer acceptance.
2. Verify the chosen input, processing and delivery route with non-sensitive sample material, including intended and unauthorized recipient checks. Existing contact storage does not establish this capability.
3. Complete provider sandbox payment, failure, uncertain/repeated attempt and refund checks with independent readback. The helper currently models full upfront payment of the USD engineering cap; deposits and additional tax/fee lines require matching validation changes.
4. Verify exact-version customer acceptance, delivery, correction and closure across the actual selected tools.

This release is a working preparation and review aid for a manually coordinated pilot. It is not live checkout, a private case-processing release, enforceable permission terms, verified signature collection or a court-readiness certification.
