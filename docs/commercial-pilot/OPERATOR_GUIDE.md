# Run one document pilot

Keep one active paid pilot. Offer one affidavit draft, timeline or dossier, with bounded engineering time at $250/hour. All three document tools are currently in their test phase; the chosen tool's actual release permissions govern its use.

**Every open order needs one owner, one next action, a due date and an evidence reference.** HubSpot holds the commercial coordination record. The protected business record holds the scope, acceptance and private documents. GitHub holds code and blank templates.

| Step | Do this | Advance only when |
| --- | --- | --- |
| **1. Request** | Confirm the document category, fit and available hours. Create a deal only for a concrete opportunity. | There is a bounded request and capacity to consider it. |
| **2. Scope** | Complete the [scope and use template](SCOPE_AND_USE_TEMPLATE.md): deliverable, cap, date, permissions, handling, correction and cancellation/refund terms. | The owner releases the terms and the customer accepts that exact version. |
| **3. Ready** | Check payment against the provider record; confirm permitted inputs, processing route and capacity. | Amount, currency, engagement and payment state match the accepted scope. Sandbox payment never counts as real payment. |
| **4. Work** | Produce the agreed output and review source fidelity, readability and stated limits. | A numbered output version meets the completion criteria and has a recorded release decision. |
| **5. Deliver** | Deliver the released version through the agreed route. | Delivery is evidenced. Keep receipt and acceptance as separate observations. |
| **6. Close or correct** | Record the customer's response, correct the affected version or explain the actual closing outcome. | Latest-version acceptance or a documented alternative outcome exists; outstanding refunds, corrections and access actions remain visible. |

Store only coordination metadata in HubSpot: contact reference, output category, owner, next action, due date, workflow phase, and opaque scope/payment/delivery references. Keep case narratives, identity documents, signed agreements, private access URLs and tokens out of CRM notes. Do not edit the server-managed participation summaries.

HubSpot's native sales stage measures the sale. It does not prove that work was delivered, accepted or corrected. Record the six-step document workflow separately. Any validator or checklist assists review; it does not prevent a person from editing HubSpot directly or establish payment, authorization or signature validity by itself.

Handle exceptions in the same record:

- **Scope changes:** pause affected work; revise the version and obtain fresh acceptance. Earlier acceptance does not authorize changed work.
- **Uncertain payment or delivery:** reconcile the provider record before retrying. Never assume a timeout means failure or send/charge twice blindly.
- **Correction:** identify the affected version, preserve its history, review and deliver the new version. Earlier acceptance does not apply to the corrected output.
- **Cancellation:** record cancellation separately from successful completion; track any refund to its actual provider outcome.
- **No response:** leave an awaiting-response action or record the real closure reason. Do not invent acceptance.

Each working day, look at the next action. Once a week, check capacity, payments, unanswered deliveries and corrections. This is a manual operating rhythm, not a new automation or customer response promise.

Before the first real paid order, verify one fictional order through the chosen payment and delivery paths. A local test or completed checklist is not proof of real private document access, customer acceptance, live payment or court readiness. Consult the current release record for the remaining gates.
